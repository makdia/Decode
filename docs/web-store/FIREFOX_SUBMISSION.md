## 1. Build the Firefox zip

```bash
npm run zip:firefox
# Output: decode-firefox.zip in repo root
```

This runs the Chrome build first, then copies `dist/` → `dist-firefox/` and swaps in the Firefox manifest (`sidebar_action` instead of `side_panel`, etc.).

```
Decode is a Firefox extension built for people learning to code.

Highlight a confusing snippet on GitHub, Stack Overflow, MDN, a blog —
anywhere — right-click, and a sidebar slides in with a plain-English

WHAT IT DOES

• Highlight code → right-click → "Decode this code" → streaming explanation
• Keyboard shortcut: Cmd+Shift+E (Mac) or Ctrl+Shift+E (Windows/Linux)
• Normal mode (technical but plain-English) and ELI5 mode (everyday analogies)
• Auto-detects programming language from page markup
• Sidebar UI — explanation streams in next to the page you're reading

PICK YOUR PROVIDER

Decode supports two LLM providers — switch any time in settings:

• Anthropic Claude (paid, ~$0.001 per explanation on Haiku)
• Groq Llama 3.3 70B (free tier — no credit card needed)

You bring your own API key. Decode does not charge you anything.
Get a free Groq key at https://console.groq.com/keys to start at zero cost.

PRIVACY

• Your API key is stored locally with browser.storage.local — never transmitted to us
• No analytics, no tracking, no telemetry
• We have no servers — nothing to phone home to
• Code you highlight goes only to the LLM provider you chose (Anthropic or Groq), nowhere else
• Open source under MIT: https://github.com/makdia/Decode
• Privacy policy: https://makdia.github.io/Decode/privacy/

WHO IT'S FOR

• Bootcamp grads decoding tutorial code
• Self-taught developers reading open-source projects
• CS students stuck on textbook examples
• Anyone who hits "I have no idea what this does" and doesn't want to break their flow
```

## 4. Source code disclosure (AMO-specific)

AMO requires source code upload for review when your extension is built/bundled (which ours is — Vite + TypeScript).

You can either:
- **Provide the GitHub URL** (`https://github.com/makdia/Decode`) and link to the exact tag (`v0.1.0`)
- **Upload a source-code zip** that includes everything needed to reproduce the build:
  - `package.json`, `package-lock.json` (or `pnpm-lock.yaml`)
  - All `src/`, `public/`, `manifest.firefox.json`
  - Build instructions

To make this easy, AMO accepts a README in the source zip pointing to the GitHub repo:

```bash
git archive --format=zip --output=decode-source-v0.1.0.zip v0.1.0
```

(Tag `v0.1.0` already exists from when we cut the GitHub release.)


## 6. Permission justifications

Same as Edge — AMO is more lenient but uses similar fields:

| Permission | Why |
|---|---|
| `contextMenus` | To register the "Decode this code" right-click item on text selections. |
| `storage` | To save the user's API key, model preference, and explanation history locally. |
| `activeTab` | To read the user's text selection on the active tab when they trigger Decode. |
| `scripting` | Used by the content script to inspect DOM class names so we can auto-detect the programming language. |
| Host permission for `<all_urls>` | Required because the user can highlight code on any website. Decode only acts on text the user explicitly selects — it does not read or modify page content otherwise. |

## 9. AMO review expectations

- AMO reviewers are usually faster than Chrome (1-2 days, sometimes hours)
- They are stricter about: minified code without source, missing build instructions, undisclosed remote-code execution
- We are clean on all three (open source, build instructions provided, no remote-code-eval)
- Open-source extensions with public GitHub links often get fast-tracked
- If they ask for changes, the feedback is usually specific and actionable

## 10. Submission flow

1. Go to https://addons.mozilla.org/developers/addon/submit/
2. Choose **On this site** (listed publicly) vs **On your own** (self-hosted)
   → choose **On this site** for AMO listing
3. Upload `decode-firefox.zip`
4. Choose **Specify compatible applications** → Firefox only (skip Android unless you want to)
5. Upload source code zip OR provide GitHub URL with v0.1.0 tag
6. Paste build instructions (section 5 above)
7. Fill listing fields (sections 3, 6, 7, 8)
8. Submit for review
